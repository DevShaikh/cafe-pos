# Implementation Plan

## Objective
Translate an approved approach into a precise implementation plan.

## Procedure
1. Review the investigation findings.
2. Confirm the user's selected approach.
3. Inspect the latest relevant source code.
4. Identify exact files and components likely to change.
5. Describe required frontend, backend, database, and Electron changes.
6. Identify API compatibility and data migration implications.
7. Identify edge cases and failure scenarios.
8. Define targeted tests and verification commands.

## Plan Format
Present:
- Objective.
- Scope included.
- Scope explicitly excluded.
- Files expected to change.
- Implementation steps in order.
- Risks and dependencies.
- Test strategy.
- Expected outcome.

## Restrictions
- Planning only; do not edit files.
- Do not introduce unapproved features.
- Do not assume implementation details without inspecting source.
- Ask before consequential architecture or database decisions.

Wait for explicit implementation approval.
